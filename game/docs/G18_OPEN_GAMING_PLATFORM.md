# G18 OPEN GAMING PLATFORM

Owner-approved G18 design direction; implementation pending. Engineering contracts, candidate algorithms and schemas below are documentation-only proposals, not runtime code. Existing source, assets, saves and gate completion statuses are untouched.

## Product and ownership
Build our own independently controlled open-source gaming platform from the ground up, not a Steam dependency or copy of Steam branding/code. Start AOMW-specific, modular for later games/expansions. Owner controls repo, domains, keys, data export, deployment, hosting choice and release decisions. Open-source license selection is pending; distinguish copyright ownership, license grants, trademark, dependencies and game assets. No claim exclusive downstream control once open sourced. Do not require third-party store accounts. Reuse audited open-source libraries/standard protocols rather than reinvent crypto or transport. Platform is optional for offline play.

## Launch capabilities
Identity (account creation/login, verified recovery, session revocation, optional MFA), profiles (display name/avatar, privacy), friends, block/report, invites, public/private lobbies, matchmaking/filter, route allocation, relay fallback, reconnection and host migration coordination, version/content compatibility, optional community dedicated host registration, support diagnostics and minimal administration. Launcher/distribution: proposed small self-owned launcher or game-integrated client, signed release manifest, hash verification, resumable downloads, patch/rollback, separate game entitlement receipts, offline local verification for legitimate installed content; public website/docs and platform repo. Free Workshop/Creator Store, game library, launcher, replay catalog, minimal owner developer portal, versioned SDK/API and chosen game/DLC commerce and entitlement solution are required launch scope. Broader third-party publishing, paid creator commerce, reviews and Steam-sized social/storefront features are phased, not mandatory for G18. See [platform product roadmap](PLATFORM_PRODUCT_ROADMAP.md). No mandatory cloud inference, persistent game worlds, voice infrastructure or always-on match servers.

## Lean service design (proposed)
One modular control-plane service plus durable transactional DB, static artifacts on object storage/CDN or self-hosted mirror; one or more on-demand relays, optional headless community hosts. Start small, scale horizontally only from measured usage. Stateless API where possible; isolated relay credentials; service discovery via configurable endpoint; regions only as needed. Avoid unnecessary microservices/containers/orchestration. Clients host simulation; backend stores minimal account/social/lobby/entitlement metadata, not every simulation tick. Use TLS, mature authentication library, salted adaptive password hashes, secure token handling, rate limits, validation and audit logging; no secret keys in client. Backups with restore drill, admin role separation, least privilege, dependency update policy, signed build pipeline, incident/revocation plan. Account deletion/export, data retention and privacy policy, block/report and abuse controls; do not publicly reveal IP/address unnecessarily; relay option for privacy. Protect against spam, credential stuffing, denial of service and resource exhaustion; bounded quotas, short-lived route tickets, relay byte/session caps and operational alerting. Do not claim absolute anti-cheat/availability.

## Cost discipline
Default direct host sessions, relays only when required or chosen, region selection based on measured demand. Traffic budget model: relay monthly GB = relayed session-hours × measured aggregate billed GB/hour (include both directions/provider egress rules); monthly cost = fixed hosting + DB/backups + artifact delivery + relay compute/egress + domains/monitoring + support/abuse overhead. Track peak concurrent sessions, relay fraction, bytes/player-minute, average duration, egress, login/match requests and storage. Example scenario only: 100 relayed session-hours × 0.2 GB/h = 20 GB; actual rate and cost unknown until prototype and provider quotes. Set founder-approved monthly spend cap and traffic alert, idle shutdown, per-session abuse limits, graceful queue/route fallback, never silently cut an active match for ordinary budget limits. Test relay-only and direct connectivity, measure costs and evaluate self-host vs low-cost VPS before procurement. No guaranteed free operation. Document recovery and data portability; provider-specific adapter behind interface.

## Release and operational acceptance
Reproducible build, license inventory, contributor policy, secret rotation, security review, signed updates, rollback and backup restoration; onboarding and support docs, accessibility, account deletion, moderation, endpoint outage and offline fallback. Operate under owner-controlled accounts; no deployment/account creation in this documentation pass. Actual platform name, license, service stack, provider, budget, payment and launch jurisdiction policies require production decisions. No mandatory platform login for offline solo.
