# G21 delivery and release acceptance
Planned after G20 acceptance. No dates, implementation or test claims. Preserve G10.1 stabilization and G11–G20 scope/order. Earlier gates may expose compatible interfaces only through their existing owner-reviewed contracts; no premature G21 implementation.
| Phase | Exit evidence |
|---|---|
| G21.1 | Audit source and contracts; migrate representative G20 saves; stable IDs, mutable registry, deterministic scheduler and budgets validated |
| G21.2 | First planetary transformation playable, visible and persistent; occupied terrain and recovery tested |
| G21.3 | Engineering fleets and Dyson projects functional; resource conservation, damage, takeover and acceleration tested |
| G21.4 | Artificial worlds/rings/system assembly and late stellar projects playable; navigation and tier transitions validated |
| G21.5 | Fictional splicing, hybridization, original species and ecosystem creation validated |
| G21.6 | Civilization seeding, independent development, diplomacy, lineage and language integration validated |
| G21.7 | Generated factions have complete functional modular economy, construction and combat rosters |
| G21.8 | Great Filter, protectorates, engineering operations and War of Architects emerge from actual state; Vhessar and other AI use fair constraints |
| G21.9 | Optional laboratory, observatory, library, achievements and mode presets integrated; safe declarative imports and entitlement tests |
| G21.10 | Full offline package, regression, migration, replay, native/fallback parity, performance and gameplay acceptance |
Release only after complete polished expansion. Freeze measurable budgets, GOAL and Done-when before work. Test early-to-late capability changes, no mandatory micromanagement, AI parity, meaningful wars, failure/recovery, long-run bounded simulation and preservation of earlier content. No separate public phase releases.
